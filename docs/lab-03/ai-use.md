## My Reflection

งาน Lab 3 ใช้ opencode ช่วยออกแบบ เขียนโค้ด เขียนเทส และตรวจงาน แต่บทบาทของฉันคือ ตั้งคำถาม ตัดสินใจ และยืนยันผลทุกขั้นตอน

**1. เทสที่ดีต้องไม่ผูกกับข้อมูล seed แบบตายตัว**
- เทส `change-password` ที่ไปแก้รหัสบัญชี seed จริง ๆ จะทำให้ MIG-01 (ซึ่ง assert สภาพทั้งตาราง) ล้มทั้งชุด → วิธีที่ถูกคือใช้ **throwaway user** แล้วลบใน `afterAll` และเกณฑ์เดียวกันนี้ถูกใช้ซ้ำกับเทส 409 last-admin (prompt 5, 7)
- บทเรียนคือ **อย่าทำให้เทสอ่อนลง** เพื่อกลบ workflow แต่ให้บันทึกขั้นตอนที่ถูกต้อง (re-seed ก่อนรันเทส) ให้คนตรวจทำตามได้

**2. prompt ที่ดีต้องบังคับให้ AI สืบ ไม่ใช่เดา**
- สืบ root cause ของ CORS error ได้คำตอบจริง (ค้าง `VITE_API_URL` จาก Lab 2 ที่ชี้ข้าม origin) ขณะที่ แก้ error นี้ให้หน่อย จะได้ patch ที่แตะโค้ดผิดจุด
- เช่นเดียวกัน การให้ AI เสนอทางเลือกพร้อมข้อดีข้อเสีย ทำให้ตัวเองเห็นประเด็นที่คิดไม่ถึง เช่น trade-off ระหว่าง re-read DB ทุก request กับการเชื่อ session

**3. AI ช่วยเจอ blind spot แต่ตัวเราเองก็ผิดได้ ต้อง verify ทั้งสองทาง**
- prompt self-review เจอ 6 จุดที่ตัวเองมองข้าม แต่รอบเดียวกันก็เจอว่าที่เราสั่งให้ลบ ("null check ซ้ำ") เป็น **type-narrowing guard** ที่ TypeScript ต้องใช้ ถอดแล้ว build พัง
- peer review ก็เช่นกัน ทุกข้อที่เพื่อนแจ้งต้องไล่ยืนยันกับโค้ดก่อนแก้ ไม่ใช่แก้ตามที่บอกทันที
  
**4. "ผ่าน" ในคอลัมน์หลักฐาน ต้องแปลกลับได้ว่าอะไรทำให้มันผ่าน**
- ai อ้างว่า `RESP-13..15` เป็นหลักฐานว่า filters/sort/pagination ใช้ได้ ทั้งที่**ไม่มีภาพไหนเลยที่กด filter** (กล่อง filter เริ่มต้นปิด) และ `RESP-25..27` เป็นหน้า Requester ไม่เกี่ยวกับ staff queue จุดพลาดคือตรวจว่า "test ID มีอยู่จริง" แต่ไม่ได้ตรวจว่า **test พิสูจน์สิ่งที่อ้างหรือไม่**
- กฎ: ก่อนเขียนคำว่า Pass ให้คิดว่า *"ถ้าให้ reviewer เปิดหลักฐานที่อ้าง จะเห็นอะไร"* ถ้าไม่เห็นอะไร ก็ยัง Pass ไม่ได้ แม้ test จะเขียวหมด

### สรุปภาพรวม

AI ช่วยเพิ่มความเร็วในการ implement และทำหน้าที่ "co-reviewer" ที่ละเอียดกว่าที่ตัวเราทำคนเดียวได้ แต่คุณค่าที่ตัวเราเพิ่มเองคือ **การถามคำถามเชิงตัดสินใจกับ AI ก่อนเริ่มงาน, การตั้งเกณฑ์เทสที่กำหนดพฤติกรรมของระบบ, และการไล่ตรวจผลของ AI ทุกครั้งก่อนปิด** lab นี้ทำให้เห็นว่าการใช้ AI ให้ดีไม่ใช่การ "สั่งแล้วรอรับ" แต่คือการทำงานร่วมกันแบบที่คนควบคุมทิศทางและความถูกต้อง AI
